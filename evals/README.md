# 의도분류 골든셋

`golden.jsonl`은 supervisor가 질문을 `deposit` / `loan` / `general` /
`out_of_scope` 중 어디로 보내야 하는지를 정한 정답지다.

## 라벨링 규칙

라벨은 **제품이 어떻게 답해야 하는가**로 정한다. 현재 구현이 실제로 무엇을
반환하는지 보고 맞추지 않는다. 그렇게 하면 eval이 자기 자신을 채점하는
꼴이 되어 회귀를 잡지 못한다.

| 규칙 | 내용 | 라벨 |
|---|---|---|
| R1 | 특정 상품을 **찾거나 비교**하려는 의도 (금리·기간·조건·한도) | 해당 상품군 |
| R2 | 상품 데이터 없이 답할 수 있는 **개념·제도·용어·계산법** | `general` |
| R3 | 이 앱이 **다루지 않는 상품** (주식·펀드·코인·보험·연금저축) | `general` |
| R4 | 수신·여신이 함께 나오면 사용자가 **행동하려는 쪽** | 그 상품군 |
| R5 | 인사·감사, 이 챗봇이 무엇이고 무엇을 할 수 있는지 묻는 질문 | `general` |
| R6 | **금융·경제와 무관한 전부** (날씨·코딩·번역·요리·건강·창작·잡담) | `out_of_scope` |

- 수신(예금·적금·목돈·저축)과 정책 적금·자산형성 지원(청년미래적금·청년내일저축계좌·
  청약통장 등) → `deposit`
- 여신(주택담보·전세자금·신용대출·마이너스통장·카드론)과 정책대출(햇살론·디딤돌·
  버팀목·보금자리론 등) → `loan`
- R3와 R6의 차이: 금융이지만 이 앱이 못 다루면 `general`(설명하고 안내한다),
  금융이 아니면 `out_of_scope`(거절한다). 낱말이 아니라 **요구하는 일**로 가른다 —
  "이자 계산하는 파이썬 코드 짜줘"는 `이자`가 들어 있어도 코딩 요청이라 `out_of_scope`,
  "너 뭐 할 수 있어?"는 금융 낱말이 없어도 앱 능력 질문이라 `general`이다.
- 정답이 진짜로 반반인 질문은 **골든셋에 넣지 않는다.** 채점이 불가능한
  문항은 점수를 흐릴 뿐이다.

## tier

| tier | 뜻 |
|---|---|
| `core` | 정답이 명확하고 표면 단서도 일치한다. 여기서 틀리면 회귀다. |
| `boundary` | 정답은 명확하지만 **표면 단서가 오도한다.** 예: "햇살론이 뭐야?"는 상품명이 있지만 제도 설명을 원하므로 `general`. |

`out_of_scope`는 양방향으로 틀릴 수 있어 boundary에 두 종류를 함께 넣는다 —
거절해야 하는데 답해버리는 쪽("은행원 연봉 얼마야")과, 답해야 하는데 거절해버리는
쪽("너 무슨 AI 모델이야"). 과잉거절도 회귀다.

`boundary` 정확도는 원래 낮게 나오는 게 정상이다. 이 수치를 올리려고 문항을
쉽게 바꾸면 eval이 무의미해진다. **기준선은 `core`에만 건다.**

## 갱신 원칙

- 기능이 늘거나 라우팅 정책이 바뀌면 문항을 **추가**한다. 기존 문항을
  지우거나 고치는 건 정책 자체가 바뀐 경우뿐이고, 그때는 이유를 커밋에 남긴다.
- 모델이 틀린 문항을 정답 쪽으로 바꾸지 않는다. 틀린 건 틀린 채로 두고,
  프롬프트를 고치거나 알려진 한계로 기록한다.
